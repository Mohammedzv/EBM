IBM System - نظام صيانة الماكينات
==================================

النسخة دي مربوطة بـ Firebase Realtime Database على المشروع الموجود في إعدادات index.html، وتدعم مزامنة البيانات بين الأجهزة.

الجديد في النسخة:
- العامل يضغط «إبلاغ عن توقف» ويختار الماكينة ويكتب وصف العطل.
- حالة الماكينة تتغير إلى «متوقفة» ويظهر البلاغ في قسم «بلاغات الأعطال» على كل الأجهزة المتصلة.
- الفني يضغط «وصلت للماكينة» لتسجيل وقت الوصول، ويمكنه كتابة اسمه.
- الفني يضغط «تم الإصلاح» لتسجيل انتهاء العطل وإعادة حالة الماكينة إلى «تعمل بشكل طبيعي».
- زر «تفعيل الإشعارات» يطلب إذن إشعارات المتصفح، ويظهر إشعار عند وصول بلاغ جديد على جهاز آخر.
- زر النسخة الاحتياطية يصدر بيانات النظام إلى ملف JSON.

طريقة التحديث:
1. فك ضغط IBM_System_Cloud_Sync.zip.
2. ارفع مجلد IBM_System/ أو استبدل index.html في مستودع GitHub Pages بنفس الملف الموجود داخل المجلد.
3. افتح رابط الموقع عبر HTTPS، وليس من مدير الملفات.
4. في Firebase Console > Realtime Database > Rules، يجب نشر قواعد تسمح للمسار ibmSystem/state بالقراءة والكتابة. قواعد الاختبار المفتوحة المرفقة غير آمنة للاستخدام الحقيقي.
5. افتح الموقع على كل جهاز واسمح بالإشعارات من زر «تفعيل الإشعارات».

ملاحظات مهمة:
- إشعارات المتصفح في هذه النسخة تعمل عندما تكون صفحة الموقع مفتوحة/نشطة حسب دعم المتصفح. الإشعار المضمون حتى عندما يكون الموقع مغلقًا يحتاج إعداد Web Push وService Worker وخادم إرسال موثوق، وهو غير مضاف هنا.
- اكتشاف التوقف يدوي: العامل هو من يبلغ عن العطل بزر داخل النظام؛ لا توجد قراءة مباشرة من الماكينة أو حساس.
- لا تستخدم قواعد Firebase العامة المفتوحة مع بيانات حقيقية؛ أضف Firebase Authentication وقواعد مقيدة للمستخدمين قبل الاستخدام الفعلي.
- بيانات النسخة المحلية السابقة لا تنتقل تلقائيًا إلى السحابة. صدّر نسخة احتياطية قبل التحديث إذا كانت لديك بيانات مهمة.
