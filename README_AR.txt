IBM System — إشعارات Push بالخلفية
==================================

هذه النسخة تضيف إشعارات FCM تصل للجهاز المسجل حتى لو صفحة الموقع ليست مفتوحة، عن طريق Service Worker وCloud Function.

الملفات المهمة:
- index.html: واجهة النظام وتسجيل جهاز المتصفح لاستقبال الإشعارات.
- firebase-messaging-sw.js: استقبال الإشعارات بالخلفية.
- functions/index.js: خدمة الخادم التي ترسل إشعارًا لكل جهاز مسجل عند إنشاء بلاغ توقف جديد.
- functions/package.json وfirebase.json و.firebaserc: إعدادات نشر الوظيفة.

خطوات الإعداد:
1) ارفع محتويات مجلد IBM_System إلى جذر مستودع GitHub Pages، مع استبدال الملفات القديمة. يجب أن يكون الموقع على HTTPS.
2) افتح الموقع من كل جهاز/متصفح تريد أن يستقبل إشعارات. اضغط «تفعيل الإشعارات والصوت» واسمح بإشعارات المتصفح. كرر ذلك لكل جهاز مرة واحدة.
3) نشر وظيفة الإرسال يتطلب جهاز كمبيوتر أو بيئة فيها Node.js وFirebase CLI، وتسجيل الدخول لنفس مشروع sstmy-627dc:
   npm install -g firebase-tools
   firebase login
   cd IBM_System
   cd functions && npm install && cd ..
   firebase deploy --only functions
4) نشر Cloud Functions قد يتطلب ترقية مشروع Firebase إلى خطة Blaze وربط حساب فوترة، حسب إعدادات Google الحالية. راجع التكلفة وحدود الاستخدام قبل التفعيل.
5) بعد نشر الوظيفة، جرّب بلاغًا جديدًا. يجب أن تصل إشعارات للأجهزة التي فعّلت الإشعارات وسجّلت رموزها في قاعدة البيانات.

مهم:
- المفتاح المضاف في index.html هو Web Push public key (VAPID public key)، وهو ليس مفتاحًا خاصًا.
- إشعارات الخلفية لا تضمن صوتًا مخصصًا؛ صوت الإشعار يعتمد على إعدادات نظام التشغيل والمتصفح.
- الإشعارات لن تصل لجهاز لم يمنح إذن الإشعارات، أو تم إيقاف إشعارات الموقع عنه، أو إذا منع النظام عمل المتصفح في الخلفية.
- قواعد قاعدة البيانات الحالية مفتوحة للاختبار وتسمح بقراءة/كتابة البيانات والرموز؛ لا تستخدمها في مصنع فعلي قبل إضافة Firebase Authentication وقواعد أمان مقيدة.
- لا تضع مفاتيح Admin أو Service Account داخل ملفات الموقع أو GitHub Pages.
